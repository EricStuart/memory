## 脚本分析与分镜

- **MARA/CASSIAN 角色缺失**：原始 Step 8 已返回 `MARA`，真正的第一次丢失发生在 Worker 的精确规范名过滤；目录名带括号或别名时必须使用统一 canonical-name 解析。修复后还要重跑分析和下游拆镜。
- **`presentObjects` 链路**：结构分析 -> `presentObjects` -> 物理在场时间线 -> enter/exit 标记 -> `splitShotsFromStructuredScript()` -> shot readback。非空 `presentObjects` 类别应视为权威来源。
- **screen-text 合约**：Step 1 负责载体分类，Step 2 必须从 `originalFormat` 恢复 `sourceText`，最后再注入版本名；缺少 carrier 或原文来源时应阻断并产生可重试错误。
- **版本注入**：保护文本跨度时，找不到过渡 token 必须返回偏移量 0；不能用 `lastIndexOf(token) + token.length` 产生伪偏移。
- **descriptionType**：Step 1 输出对话/动作、描述、非主体和删除判定；Step 2 再细分对话与动作。普通描述不应改变物理在场，旧的 `state-change` 只能作为兼容读取值。
- **Step 5 合并**：LLM 只能返回带 `sourceSegmentIds`、`sourceGroupId` 的受限同时合并计划；跨组、重复消费、类型非法或过度压缩时必须回退原始片段。
- **extract_objects**：要区分 Worker 完成、reducer 提交和任务成功三个边界，检查空结果、旧引用和“假成功”。
- **split_scenes / split_shots**：先确认迁移和 schema 状态，再判断边界算法；语言长度、目标语言和音频可用性必须明确为产品输入，不能混用字符数假设。
- **enter/exit 标记**：先读取已持久化文本和版本，再追溯生成器、标记合并和 UI 隐藏规则；历史数据需要明确的重跑或回填计划。

## 个人身份、支付与产品

- **个人微信 OAuth**：仅用于个人门户，使用 Open Platform 的 `unionid` 优先、`openid` 兜底；工作室和管理员认证保持独立。生产 callback 必须使用 HTTPS 正式域名。
- **PC 支付第一阶段**：范围是微信 Native 二维码和支付宝，支持手动续费；订单创建使用同源校验、UUID 幂等键、账户级锁和 provider claim。退款、权益回收和真实商户联调另行处理。
- **支付宝生产防护**：调用签名、商户 seller 校验、主动 query/close、金额/币种校验和终态同步都必须 fail-closed。
- **微信支付**：V3 回调需要 serial-aware 验签、appid/mchid 校验、订单查询和权益发放事务。
- **计费后台**：基础配置、权益说明、前端展示分离；充值点数与倍率双向计算，预览栏在窄屏下可折叠。
- **批量镜头润色**：一次最多 200 个镜头，为每个目标创建精确任务；自定义 prompt 只在本次请求生效，canonical `storyboard_text` 仍按镜头写入。

## 运行、Git 与验证

- 完整本地栈要同时验证 Web/Gateway/NATS/PostgreSQL/PostgREST、Scheduler、Worker、Projector 和健康端点。
- Node 26 的 Windows `--import` 参数必须使用 `file:///D:/...` 形式，不能直接传 `/d/...` 或普通磁盘路径。
- 脏工作区同步采用 stash（含未跟踪文件）-> fetch/merge 或 rebase -> 恢复 -> 语义解决冲突；不要丢弃用户改动。
- 中文提交、普通 rebase、非交互式推送和最终 `0 0` 分歧检查是稳定交付流程。
- 只要远程 SSH 或浏览器认证不可用，就应明确标注“本地已验证、远程未验证”，不得扩大完成结论。
